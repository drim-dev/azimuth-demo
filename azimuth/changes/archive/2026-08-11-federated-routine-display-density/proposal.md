# Change: federated-routine-display-density

Status: **accepted and complete**

## Problem

The federation experiment needs a product-like routine change whose intent and implementation are
owned wholly by the rider experience. A synthetic manifest alone cannot establish that the normal
application path remains light.

## Scope

Add compact and comfortable display-density choices to the rider masthead and remember the choice
in browser-local storage. Density changes spacing only. It does not alter requests, authorization,
prices, trip state, referral state or server contracts.

## Criticality rationale

The requirement is routine because an incorrect choice inconveniences one browser and can be
reselected without changing system state. Raise it if density begins to hide information or becomes
an accessibility conformance obligation.

## Completion

- both choices are named and keyboard operable;
- a choice is restored after reload;
- implementation builds in the production frontend bundle;
- the claim adds no realization, evidence, design, verification or judgment declarations;
- the accepted intent is applied and the change is archived.
