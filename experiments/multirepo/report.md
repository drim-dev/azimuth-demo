# Federation trial report

Date: 2026-08-11

Status: **machine boundary strengthened after adversarial failures; six cold routing tasks pass;
independent-team adoption remains external evidence**.

## Results

The executable conformance suite passes 31 scenarios. It creates independent Git histories rather
than mocking revision strings. The largest scenario assembles 50 repositories, 50 model sources,
50 areas and 5,000 typed sources inside a 30-second bound.

An adversarial static pass initially found five false-green classes: semantic validation lived
outside the snapshot method, untracked/ignored model files could evade the revision account,
receipt tuples were not closed-world, owned paths could escape a repository, and assembly trusted a
producer's enclosing mount. Each boundary is now enforced in assembly/finalization and has a
regression test. Missing inputs, altered digests, revision skew, receipt skew, area conflicts,
source conflicts, model-source drift, duplicate spec ownership and unsupported versions all fail
before finalization.

The monorepo control and federated configuration derive equal claims, relations and holes. The
federated and centralized split configurations both assemble a correct complete model. Only the
federated configuration exposes experience intent to an experience-local routine check. This is
positive evidence for federated model sources and negative evidence for a mandatory centralized
model repository.

Moving the complete `rider-experience` area into a new repository preserved the critical receipt
claim's judgment fingerprint. Changing an area's identity is not treated as the same operation;
the catalog/source join fails until an explicit new identity is supplied.

The real rider application now implements the routine `experience/display-density` requirement.
It changed an untagged layout site and added no traceability, design, verification or judgment
artifact. Frontend type checking and the production build pass.

## Interpretation

The machine-tier abstractions are feasible and internally coherent. Areas earn their cost by
separating stable source identity from repository and path locators. Required-input catalogs and
revision-bound receipts are necessary: without either, a partial workset could be mistaken for a
complete account or composed evidence could float across release candidates.

The first cold routine agent got the obligations right but could not discover its exact area or
model-source id. The physical split had put all intent in backend and left other checkouts with
instructions pointing to absent files. F8 therefore fired. A second run exposed ambiguous relative
locator use and a missing local executable. The corrected materializer now moves experience intent
and its archive to `rides-experience`, copies usable formats and instructions, puts the singular
catalog in `rides-assurance`, and adds a repository-local project reference plus executable
`project locate`. A third fresh agent then found the exact authority, area and routine obligations
without a corrective prompt. Another attempted critical run is not counted because its prompt
disclosed the expected topology.

The corrected baseline then passed all six tasks in the recorded cold protocol without a structural
corrective prompt, duplicate proposal/spec authority or false finalization. A standard projection
stayed system-owned while recognizing its rider surface; an operations task treated its alert as
detection evidence rather than realization; a critical refund task selected one system-intent
authority and four bounded repository packages; backend and experience package agents stayed within
their assignments; and an assurance-started claim-hole task routed the repair to existing Payments
component evidence instead of manufacturing an E2E test. The operations task also found that a host
`promtool` was absent, so the materialized operations repository now provides a pinned-container
rule-test wrapper. These are replicated agent-routing results in one fixture, not evidence that an
independent organization has adopted the operating model.

F6 is supported only at the identity boundary: an area-id change cannot masquerade as a locator
move. The framework does not yet require a particular archived topology-change artifact. F7 is now
established mechanically: complete observations cannot omit their tracked changes and duplicate
change ids fail across repositories.

The critical cold task found a related lifecycle gap: repository-local change archiving advances a
revision after the complete project tuple was checked. `project accept-change` now verifies the
complete pre-archive and post-archive worksets as one transition. It requires a fresh exact-revision
receipt after the archive, rejects unrelated revision movement, and emits the post-archive snapshot.

The final physical split preserves root ignore policy in every repository, so compiling the shared
CLI or product code does not make a selected repository revision appear dirty. Repository-local
routine checking and the operations rule-test wrapper both pass from their generated checkouts.
The revised observer also ran against that physical split and derived the display-density archive
from `rides-experience`; the manifest did not need a hand-authored change list.
