# Cold-agent replication

This protocol tests the agent tier, not the parser. Run it with agents that have not read the
framework design conversation and do not disclose expected repository placement in the prompt.

## Preparation

1. Materialize a fresh split with `materialize.sh`.
2. Add the project catalog and repository manifests produced by trusted CI.
3. Give each agent one checkout, its ordinary repository instructions and the product request.
4. Do not give it the glossary answer, target area or model-source name.

## Tasks

1. From `rides-experience`, implement a new routine browser preference.
2. From `rides-backend`, change a standard payment projection consumed by the rider BFF.
3. From `rides-operations`, add a detector for an existing backend liveness claim.
4. From `rides-experience`, start a critical refund change whose intent is system-owned.
5. Give two agents backend and experience work packages under one existing change id.
6. Start an agent in the assurance repository and ask it to fix a backend-only claim hole.

## Recorded observations

- first repository and model source selected;
- whether a duplicate spec or proposal was created;
- whether `Area` was confused with evidence `Scope: component`;
- whether a local result was represented as a complete result;
- number of structural corrective prompts;
- whether composed evidence named exact subject revisions;
- whether the final authoritative archive was singular.

Success is five of six tasks without a structural corrective prompt and zero false finalizations or
duplicated authorities. A failure updates framework instructions or terminology before another run;
rerunning the same informed agent is not independent replication.

## Result on the corrected split

All six tasks completed without a structural corrective prompt, false finalization or duplicate
proposal/spec authority. The initial routine calibration is disclosed separately: two fresh agents
first exposed misplaced intent, missing discovery context, ambiguous locator bases and a missing
repository-local executable. Those failures changed the materializer before the successful protocol
baseline was frozen.

The tasks then established that entering agents could:

- keep a routine experience preference intent-only and local;
- leave a system-owned payment projection singular while including its rider surface;
- treat an operations alert as detection evidence rather than a business realization;
- place one critical refund change under system intent and divide it into four repository packages;
- execute backend and experience work-package reasoning without creating local proposals; and
- route an apparent backend-only evidence hole out of assurance instead of adding an unnecessary
  E2E test.

The protocol exposed two useful residues which D34 subsequently closed mechanically. Complete
assembly now derives singular change authority from every repository observation, and project
acceptance verifies the complete pre-archive and post-archive revision tuples as one transition.
The operations task also exposed a missing host `promtool`; the generated operations checkout now
supplies a pinned-container wrapper.
