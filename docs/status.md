## What was actually demonstrated

**The site-class result, and it is the only strong one.** The residual in
`verification/trips/rider-view.md` predicted, before any application code existed, that a new
rider-reachable surface would satisfy every behavioural claim and leak anyway. Slice 2 built the
receipt; the matrix reported 23 errors before and 23 after. The invariant designed against that
evidence found all seven sites in the class and named the three that leaked.

That is a pre-registered prediction, confirmed, catching a real privacy defect that would have
shipped. It is also the clearest statement of what per-scenario tracing structurally cannot do: a
claim quantified over a *set of sites* is not established by evidence about one site, however good
that evidence is.

**Five decisions were revised by evidence rather than argument** — D12, D13, D14→D18, D15, and D7's
identity. That is the method working: notation last, evidence first.

**The agent tier found four defects on a matrix the machine tier called green**, and one of them
survived its own fix. Encouraging, and see the validity note below.

## What is compromised about all of it

One agent designed the framework, wrote the fixture, wrote the tests, tagged the code, and judged
its own tags. Every source of validity is weak except the pre-registered prediction — and the same
author wrote both the prediction and the leak that confirmed it.

The agent-tier result reads well and is the same author finding flaws in their own work an hour
later. That is *some* evidence the pass has value. It is not evidence that it works reliably, which
is what the falsifier asked for.

**Nothing further from this repo can settle it.** The demo can show a mechanism exists and can
demonstrate a class of defect it catches. It cannot show that the holes are real defects rather
than an artifact of having designed the fixture to have them.

## Honest gaps

- **26 claims unjudged.** The verify pass was run on `payments/capture` only.
- **`invariant-breach` verifies the weakest rung of the enforcement ladder** — a guard at every
  site. A choke point every member routes through would report N−1 breaches, which is exactly the
  defect D7 names in the alpha. Crediting one needs call-graph analysis in the extractor (D10.1).
- **The quotes table was not split** with the pricing service. `design/trips/request.md` predicted
  this would be the first thing to break, and it is.
- **The criticality mechanism is not working** on current evidence, and no counter-pressure was
  ever built (D6.6 decided that there must be one and left the mechanism open).

## What would settle it

1. **Retrofit onto a codebase this author did not write.** Several sit in `~/drim`. Days, not
   months, and it tests the one thing the demo structurally cannot.
2. **A second person, on their own code.** The accountability model is organizational and cannot be
   validated at N=1 — D3 concedes this and this phase did nothing about it.

## Summary judgment

The framework is real and the ideas are sharper than they were. The strongest claim currently
supported is: *this catches a class of defect that per-scenario tracing structurally cannot* —
demonstrated once, by its author. Everything beyond that is unmeasured, and two of the six
falsifiers have fired.

## What is stale here *(added 2026-08-06)*

The judgments above stand. These numbers do not, and are left rather than quietly refreshed,
because re-running them is a measurement and this document reports measurements with dates:

- **The counts under "What exists"** — errors, tests, and the per-rung breakdown. The application
  was re-platformed onto EF Core, MediatR, FluentValidation and IdGen; the BFFs and the rider site
  were rebuilt as two Next.js apps; the component rung moved onto HTTP behind harnesses. Run
  `scripts/check.sh` for the current figures.
- **The cost table.** Application line count, artifact line count and the tags-per-line ratio all
  moved with that work. The ratio was the interesting number and it has not been re-derived.
- **"The quotes table was not split."** Still true, but the storage layer it describes is EF Core
  now, not hand-written SQL — so `design/` prose naming plain migrations as the mechanism behind
  two critical requirements is itself stale.

What has *not* changed: no falsifier has been retired, nothing new has been measured, and the
validity note above applies to everything in this document.
